# NixOS setup (t470p)

## How this is split

Two configurations, applied by two commands. Neither imports the other.

| Layer | File | Command |
| --- | --- | --- |
| System | `setups/t470p.os.nix` + `setups/t470p.hardware.nix` | `just os-apply` |
| Home | `setups/t470p.nix` | `just apply` |

The system owns boot, hardware, networking, audio, the login screen and the
graphical session (niri and noctalia). It does not install programs.

Terminal programs go in home-manager, under `setups/programs/`. Graphical
programs come from flatpak. Two exceptions live in home-manager: the terminal
emulator, because it hosts the terminal programs, and JetBrains Toolbox, because
it is not on flathub.

## Install on a fresh machine

1. Install NixOS from the ISO, user `elias`. The hostname does not matter, step
   6 sets it.

2. Get the tools for the first rebuild:

   ```shell
   nix-shell -p git just nh
   ```

3. Clone the repository:

   ```shell
   git clone https://github.com/trin94/nix-config.git ~/.dotfiles
   cd ~/.dotfiles
   ```

4. Replace the hardware file. The one in git has invented UUIDs and will not
   boot.

   ```shell
   sudo nixos-generate-config --show-hardware-config > setups/t470p.hardware.nix
   ```

5. Match `system.stateVersion` in `setups/t470p.os.nix` to the NixOS release you
   installed from. Read it before you switch away:

   ```shell
   grep stateVersion /etc/nixos/configuration.nix
   ```

   Never bump it later. It pins the on-disk layout of stateful services.

6. Switch. The `just` recipes read `/etc/hostname`, which is still `nixos` at
   this point, so name the flake attribute this one time:

   ```shell
   sudo nixos-rebuild switch --flake .#t470p
   ```

   This switch is what sets the hostname. `hostnamectl` cannot do it,
   `/etc/hostname` is a symlink into the nix store. After this, `just os-apply`
   works on its own. To run a recipe before the hostname matches:
   `just --set HOSTNAME t470p os-apply`.

7. Reboot. You should get the noctalia greeter with a niri session.

8. Apply the home configuration:

   ```shell
   just apply
   ```

9. Add flathub. NixOS has no option for flatpak remotes, so this stays manual:

   ```shell
   flatpak remote-add --if-not-exists flathub https://flathub.org/repo/flathub.flatpakrepo
   ```

## Daily commands

| Command | What it does |
| --- | --- |
| `just os-verify` | Build the system to `result`, change nothing |
| `just os-apply` | Switch to the new system |
| `just os-update` | Update the flake inputs, then switch |
| `just verify` | Build the home configuration to `result` |
| `just apply` | Switch to the new home configuration |
| `just update` | Update the flake inputs, then switch home |

`os-apply` and `apply` create their own generation. A broken system generation
cannot take your home configuration down with it, and the other way round.

## Things worth knowing

**The niri config is raw KDL.** home-manager writes `setups/t470p.niri.kdl` to
`~/.config/niri/config.kdl`.

**XWayland needs a helper.** The nixpkgs niri module does not start XWayland.
The system installs `xwayland-satellite` and the KDL spawns it. Remove either
one and X11 programs stop working.

**Portals come from the system.** `programs.niri` configures
`xdg-desktop-portal` system wide, so `myOS.programs.niri` stays disabled on this
host. fedora and p16gen2 still use it.

**The nvidia card is off.** `nixos-hardware`'s `common-gpu-nvidia-disable`
blacklists the 940MX and powers it down. There is no t470p module, so the config
uses the generic intel, laptop and ssd ones. Do not substitute the `t470s`, that
is a different machine.

**`programs.nix-ld` is on.** Without it, uv-managed Python and PyPI wheels with
native code (PySide6, ruff, prek) cannot find a dynamic linker. Add to the
library list in `setups/t470p.os.nix` when something fails with "could not start
dynamically linked executable".

**JetBrains IDEs come from Toolbox.** They land in
`~/.local/share/JetBrains/Toolbox` as unpatched binaries and run on nix-ld. The
desktop entries skip Toolbox's FHS sandbox, which is why the libraries have to
be in nix-ld and not only in the FHS env.

From 2026.1 on an IDE picks its own toolkit, and the fallback to X11 is silent.
`Help | About` names it: `WLToolkit` is native Wayland, `XToolkit` means a
Wayland library is missing from nix-ld. Force either mode with
`-Dawt.toolkit.name=WLToolkit` through `Help | Edit Custom VM Options`.

Do not point `IDEA_VM_OPTIONS` at a file written by home-manager. That file
replaces the bundled `.vmoptions` instead of adding to it, and the IDE loses its
heap, GC and JCEF defaults. `Edit Custom VM Options` copies the bundled file
first, so it is the safe way in.

**Password.** The user was created during install and `users.mutableUsers` stays
at its default, so `passwd` keeps working and no hash lands in git.

**python-mpv needs a patch.** `mpv.py` resolves libmpv through
`ctypes.util.find_library('mpv')`, which shells out to `/sbin/ldconfig`. NixOS
has no ldconfig cache, so it returns `None` and mpvQC raises `OSError` on
import. home-manager sets `MPVQC_LIBMPV` to the store path of `libmpv.so`. Teach
`mpv.py` to read it:

```shell
OLD="sofile = ctypes.util.find_library('mpv')"
NEW="sofile = os.environ.get('MPVQC_LIBMPV') or $OLD"
sed -i "s|$OLD|$NEW|" .venv/lib/python3.13/site-packages/mpv.py
```

`uv sync` reinstalls the package and drops the patch, so re-run it whenever
dependencies change.
